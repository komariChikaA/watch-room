# Watch Room

一个面向小型社群、朋友或社团使用的私人放映室 / 屏幕直播项目构想。

目标是实现：

- 主持人共享整个电脑屏幕、指定窗口或应用画面
- 支持播放本地视频、网页视频、PPT、游戏等内容
- 观众通过浏览器直接进入房间观看
- 支持系统声音与麦克风
- 尽量降低延迟，并兼顾中国大陆网络环境
- 不依赖商业会议平台的会议时长限制
- 后续可加入文字聊天、语音频道、房间权限和观众管理

## 实现思路

### 方案一：OBS + SRS

更适合“一个人播放，很多人观看”的放映室模式。

```text
主持人电脑
  │
  │ OBS 捕获桌面 / 窗口 / 视频 / 系统声音
  ▼
SRS 流媒体服务器
  │
  ├─ WebRTC / WHEP
  ├─ HLS
  └─ HTTP-FLV
  ▼
浏览器观众
```

主持人使用 OBS 捕获桌面、指定窗口、播放器或游戏画面，并将视频和系统声音推送到自建的 SRS 服务器。

观众只需要打开网页即可观看，不需要安装客户端。

优点：

- 对桌面投屏和视频播放都比较通用
- OBS 可以精确控制分辨率、帧率和码率
- 比传统 Zoom 类会议更适合连续播放高清视频
- 服务端可以完全自建
- 可以根据人数扩展服务器和带宽

建议第一版采用：

- 1080p
- 30 FPS
- H.264
- 4–6 Mbps
- WebRTC 低延迟播放

### 方案二：MiroTalk BRO

如果希望快速做出类似“会议链接”的体验，可以直接基于 MiroTalk BRO 自建。

```text
主持人浏览器
  │
  │ Screen Share
  ▼
MiroTalk BRO / SFU
  ▼
多个浏览器观众
```

适合：

- 临时屏幕共享
- 小规模共同观看
- 希望观众点击链接即可加入
- 同时需要聊天、麦克风等功能

相比 OBS + SRS，部署和使用更接近 Zoom，但在大量观众和长时间高清视频播放方面，流媒体架构更合适。

### 方案三：同步播放器

如果所有人都能访问同一视频源，可以不真正直播视频，只同步播放状态。

```text
             WebSocket 房间服务器
                │
       play / pause / seek
                │
      ┌─────────┼─────────┐
      ▼         ▼         ▼
    用户 A     用户 B     用户 C
      │         │         │
      └──── 同一视频源 ────┘
```

服务器只同步：

- 播放
- 暂停
- 跳转
- 当前时间
- 房间状态

视频本身由每个客户端直接读取本地文件、对象存储或 CDN。

这种方式服务器压力最低，也最容易支持大量用户。

## 推荐架构

项目后续可以采用混合方式：

```text
                     ┌─────────────────┐
                     │  Watch Room Web │
                     └────────┬────────┘
                              │
              ┌───────────────┼───────────────┐
              │               │               │
              ▼               ▼               ▼
          Room API        WebSocket         Chat
              │         播放状态同步          │
              │                               │
              ▼                               ▼
        SRS / WebRTC                    Socket.IO
              │
              ▼
          视频与屏幕
```

建议技术栈：

- Frontend: React / Vue
- Backend: Node.js / Go
- Room Sync: WebSocket / Socket.IO
- Streaming: SRS
- Broadcaster: OBS
- Voice: LiveKit / mediasoup（可选）
- TURN: coturn
- Reverse Proxy: Nginx
- Deployment: Docker Compose

## 中国大陆网络考虑

如果主要用户位于中国大陆，应优先选择大陆或大陆网络质量较好的服务器。

WebRTC 部署建议同时提供：

- UDP
- TCP fallback
- TURN
- TURN over TLS

可使用 coturn 处理复杂 NAT、校园网、公司网络和部分移动网络下的连接问题。

## 第一阶段 MVP

第一版只实现最核心的功能：

1. 创建 / 加入房间
2. OBS 推送桌面或视频
3. 浏览器低延迟观看
4. 房间在线人数
5. 简单文字聊天
6. 房间密码
7. 主持人开始 / 结束放映

之后再逐步增加：

- 多清晰度
- 弹幕
- 语音频道
- 房主 / 管理员权限
- 邀请链接
- 播放历史
- 同步播放器模式
- 本地视频文件同步
- 多房间
- Docker 一键部署

## 核心原则

本项目不追求完整复刻 Zoom。

主要目标是：

> 用更简单的架构实现“一个人投屏 / 播视频，多人稳定观看”的私人放映室。

对于大量观众，优先采用广播和流媒体架构，而不是让所有用户互相建立完整的视频会议连接。
